版本：v1.1（2026-11-13）

## 1. 專案目的

### 1.1 一句話

在同一個空間裡的一群人，用手機搶時間拍出符合題目的東西，再投票淘汰拍得最爛的人。

### 1.2 使用情境

- 朋友或同學聚會、課堂和活動破冰，大家都在同一個室內空間。
- 4～12 人，每局約 10～20 分鐘。
- 不用下載 App、不用註冊，掃 QR code 就能玩。

### 1.3 成功標準

- 第一次玩的人不需要說明，看畫面就知道現在要做什麼。
- 從開房到第一輪開始，不超過 2 分鐘。
- 一局玩完都沒有人卡住，或需要重新整理才能繼續。

### 1.4 版本範圍

| 版本 | 內容 |
|---|---|
| v1 | 開房與加入、設定、每位玩家出題、拍照、揭曉、投票、重投、淘汰、結束畫面（冠軍＋最爛照片回顧）、再來一局、斷線重連、房主轉移 |
| v2 | 大螢幕模式、音效 |
| 之後再說 | 英文介面、照片下載 |

## 2. 視覺風格

### 2.1 調性

派對感：亮色、大字、粗邊框、有彈性的動畫。像桌遊和綜藝節目，不像辦公軟體。

### 2.2 設計變數（定義在 `css/base.css`）

| 變數 | 值 | 用途 |
|---|---|---|
| `--color-bg` | `#FFF6E5` | 頁面背景（奶油黃） |
| `--color-surface` | `#FFFFFF` | 卡片 |
| `--color-ink` | `#1E1B2E` | 文字、邊框、陰影 |
| `--color-primary` | `#FF4F79` | 主要按鈕、強調（桃紅） |
| `--color-secondary` | `#FFC83D` | 次要強調、房主標籤（芥末黃） |
| `--color-accent` | `#3D7BFF` | 選取狀態、連結（亮藍） |
| `--color-success` | `#20C997` | 已送出、已投票 |
| `--color-danger` | `#F03E3E` | 倒數最後 10 秒、出局 |
| `--color-muted` | `#8A8698` | 次要文字、已出局玩家 |
| `--border` | `3px solid var(--color-ink)` | 卡片和按鈕邊框 |
| `--shadow` | `4px 4px 0 var(--color-ink)` | 硬陰影（不模糊） |
| `--radius` | `16px` | 卡片、按鈕圓角 |
| `--font` | `"Noto Sans TC", system-ui, sans-serif` | 全站字體，用 Google Fonts 載入 400、700、900 三種粗細 |

### 2.3 版面原則

- 手機優先，以寬 375px 為基準設計。大螢幕模式另外排版（見 4.9）。
- 可點擊的區域至少 48 × 48px。
- 題目是畫面上最大的字：手機 28px 以上、粗細 900；大螢幕 64px 以上。
- 倒數同時用數字和進度條顯示。剩 10 秒時變成 `--color-danger`，並且輕微跳動。
- 一個畫面只能有一個主要按鈕（`--color-primary`）。

### 2.4 動畫

- 只用 CSS transition 和 animation，時間 150～400ms。
- 揭曉照片時逐張翻開，每張間隔 80ms。
- 出局時名字卡片晃動後變灰。
- 設定 `prefers-reduced-motion: reduce` 時，關閉晃動和跳動，只保留淡入淡出。

### 2.5 音效（v2）

- 音效清單：倒數最後 5 秒的滴答聲、快門聲、揭曉、出局、冠軍。
- 畫面右上角有靜音按鈕，設定存在 localStorage。
- 預設開啟。iOS 必須在使用者第一次點擊後才能播放，在「加入」或「建立房間」時初始化。

## 3. 遊戲規則

規則全部寫在 `js/rules.js`，而且要有對應的測試（見 `docs/testing.md` 第 1 節）。

### 3.1 名詞

- **玩家**：加入房間的人，不包括大螢幕。
- **存活玩家**：還沒出局的玩家。
- **觀眾**：已出局的玩家。不用拍照，但每輪都要投票。
- **候選人**：本輪可以被投票的人，也就是本輪有送出照片的存活玩家。

### 3.2 開局

- 房主建立房間後，得到 4 位數房號。
- 玩家輸入房號或掃 QR code 加入，並輸入暱稱。
- 至少 3 位玩家才能開始，最多 12 位。
- 遊戲開始後就不能加入，只能等下一局。

### 3.3 設定（房主在等待室調整）

| 項目 | 預設 | 選項 |
|---|---|---|
| 拍照時間 | 60 秒 | 30／45／60／90／120 |
| 投票時間 | 30 秒 | 15／30／45／60 |
| 只用自訂題目 | 關 | 開／關 |

### 3.4 出題

- 每位玩家（包括房主）在等待室最多可以出 3 題，每題 1～20 字。
- 玩家只看得到自己出的題目和題庫總數。房主看得到全部，而且可以刪除任何一題。
- 抽題方式：
  - 「只用自訂題目」關閉：還沒用過的自訂題目和內建題目混在一起，隨機抽一題。
  - 「只用自訂題目」開啟：先從還沒用過的自訂題目隨機抽；自訂題目用完後，改從內建題庫隨機抽，並顯示提示。
  - 同一局不會重複出題。
- 題目如果是自訂的，畫面上要顯示「出題者：暱稱」。

### 3.5 每一輪的流程

1. **拍照**：存活玩家在時限內拍照並送出。時間內可以重拍，送出後就不能再改。
2. **超時處理**：時間到還沒送出的存活玩家直接出局，而且不占投票淘汰的名額。
   - 如果所有存活玩家都沒送出：這輪作廢，沒人出局，換新題目重來。
   - 如果超時處理後只剩 1 位存活玩家：他獲勝，遊戲結束。
3. **揭曉**：顯示所有候選人的照片，附上名字。
4. **投票**：
   - 所有玩家都要投票，包括觀眾、本輪剛超時出局的人和候選人本身。
   - 每人一票，只能投候選人，不能投自己。
   - 時間到之前可以改票，以最後一次為準。時間到還沒投就算棄權。
5. **計票與淘汰**：見 3.6。
6. **結果**：公布票數和出局者。存活玩家剩 1 人時進入結束畫面，否則進入下一輪。

### 3.6 淘汰人數與平手

本輪淘汰名額 `quota` 依候選人數決定：

- 候選人 7 人以上：`quota = 2`
- 候選人 6 人以下：`quota = 1`

**全部人都棄權**：沒人出局，進下一輪。

**quota = 1**
- 第一名只有一人：他出局。
- 第一名有多人平手：這幾個人進入重投（3.7）。

**quota = 2**
- 只有一位候選人有得票：只淘汰他。
- 第一名有兩人平手：兩人都出局。
- 第一名有三人以上平手：這幾個人進入重投，重投要淘汰 2 人。
- 第一名一人，第二名只有一人：兩人都出局。
- 第一名一人，第二名有多人平手：第一名出局，第二名平手的人進入重投，重投要淘汰 1 人。

### 3.7 重投

- 候選人只限平手的那幾位，時限和投票時間相同。
- 投票資格和 3.5 第 4 點一樣，不能投自己。
- 重投後依照需要淘汰的人數，套用 3.6 的規則判定。
- 重投又出現無法判定的平手時：無法判定的名額就不淘汰，直接進下一輪。不會有第二次重投。
  - 例：重投要淘汰 2 人，結果第一名一人、第二名平手，那就只淘汰第一名。

### 3.8 結束

- 存活玩家剩 1 人時，他就是冠軍。
- 最爛照片回顧：依輪次順序，列出每輪因投票出局者的照片，附上題目、暱稱和得票數。沒有人因投票出局的輪次就跳過。
- 房主按「再來一局」：所有玩家回到等待室，保留暱稱和設定，自訂題目清空，可以重新出題。

## 4. 畫面規格

每個畫面對應 `js/screens/` 裡的一個檔案。`main.js` 依照 `meta.phase` 和自己的身分決定顯示哪個畫面。

### 4.1 首頁 `home.js`

- 包含：遊戲名稱、暱稱輸入框、「建立房間」按鈕、房號輸入框、「加入」按鈕。
- 網址帶 `?room=1234`（掃 QR code 進來）時，自動填好房號，畫面只留暱稱和「加入」。
- 偵測到 LINE、Instagram、Facebook 的內建瀏覽器時，顯示提示：「請用 Safari 或 Chrome 開啟，才能使用相機」，並附上複製連結的按鈕。
- 錯誤提示：
  - 房間不存在
  - 房間已滿
  - 遊戲已經開始
  - 暱稱重複

### 4.2 等待室 `lobby.js`

- 包含：房號、QR code（點一下可以放大）、玩家名單（房主有標籤）、出題區、題庫數量、設定。
- 出題區：輸入框加新增按鈕，列出自己出的題目，每題都可以刪除。
- 設定：房主可以修改，其他人只能看。
- 房主專屬：踢人（名單上每個名字旁的 ×）、刪任何人的題目、「開始遊戲」按鈕。
- 開始條件：未滿 3 人時，按下按鈕會提示「至少要 3 個人才能開始」。

### 4.3 拍照 `capture.js`

- **存活玩家**看到：
  - 輪次
  - 倒數（數字加進度條）
  - 題目和出題者
  - 相機取景框（3:4 直式）
  - 快門鈕
  - 切換前後鏡頭鈕
  - 「已交 x / y」
- 拍完後的預覽畫面：「重拍」和「送出」兩個按鈕。
- 送出後：顯示自己的照片縮圖和「已送出，等其他人」。
- 預設開後鏡頭，前鏡頭的預覽要左右鏡像，存下的照片不鏡像。
- 相機權限被拒絕時：顯示說明，告訴使用者怎麼到瀏覽器設定裡打開權限。
- **觀眾**看到：題目、倒數、每位存活玩家是否已送出。不顯示相機。

### 4.4 揭曉 `reveal.js`

- 照片牆：手機上兩欄，每張照片附名字，點一下可以放大。
- 顯示本輪超時出局的名單。
- 停留 8 秒後自動進入投票。

### 4.5 投票 `vote.js`

- 照片牆和揭曉一樣，點照片就是投票，被選中的照片會有藍色外框和勾勾。
- 自己的照片變灰，不能點。
- 顯示倒數和「已投 x / y」。
- 重投時標題改成「平手！再投一次」，只顯示平手的人。

### 4.6 結果 `result.js`

- 依票數由高到低列出候選人，出局者標紅。
- 顯示「存活 n 人」。
- 平手或全部棄權時，顯示「這輪沒人出局」。
- 停留 6 秒後進入下一輪，或進入結束畫面。

### 4.7 結束 `ending.js`

- 依序顯示：
  1. 冠軍
  2. 最爛照片回顧（一次一張，可以左右滑，也會每 4 秒自動切換）
  3. 房主的「再來一局」按鈕。其他人看到「等房主開新局」。

### 4.8 共通元素

- **連線狀態**：斷線時，頂部顯示「連線中斷，重新連線中…」。
- **身分標示**：觀眾的畫面頂部常駐「你已出局，繼續投票吧」。
- **被踢出時**：回到首頁並提示。

### 4.9 大螢幕模式 `bigscreen.js`（v2）

- 網址：`index.html?mode=screen&room=1234`，或在首頁選「大螢幕模式」後輸入房號。
- 大螢幕不是玩家，不能投票，也不算進人數。但它會參與遊戲推進（見 5.2），是最穩定的推進者。
- 以 16:9 橫式排版，各階段顯示：

| 階段 | 大螢幕顯示 |
|---|---|
| 等待室 | 超大 QR code、房號、玩家名單、題庫數量 |
| 拍照 | 超大題目與出題者、倒數、每位玩家的送出狀態（已送出的人亮起） |
| 揭曉 | 照片牆，逐張翻開 |
| 投票 | 照片牆和「已投 x / y」，不顯示即時票數 |
| 結果 | 出局者照片放大、票數動畫 |
| 結束 | 冠軍和最爛照片回顧，自動輪播 |

## 5. 技術架構

### 5.1 遊戲階段（狀態機）

`meta.phase` 只能是以下值：

```
lobby → capture → reveal → vote ─┬─→ result ─┬─→ capture（下一輪）
                                 │           └─→ ending（剩 1 人）
                                 └─→ revote → result

capture 超時處理後：
  全部沒交 → capture（同一輪、換題目）
  只剩 1 人 → ending

ending → lobby（再來一局）
```

| 階段 | 進入時寫入 | 結束條件 |
|---|---|---|
| `lobby` | 清空本局資料 | 房主按開始 |
| `capture` | 抽題、`phaseEndsAt` = 現在 + 拍照時間 | 時間到，或所有存活玩家都已送出 |
| `reveal` | 超時出局結果、本輪候選人 | 8 秒 |
| `vote` | `phaseEndsAt` = 現在 + 投票時間 | 時間到，或所有在線玩家都已投票 |
| `revote` | 重投候選人、要淘汰的人數 | 同 `vote` |
| `result` | 計票結果、出局者 | 6 秒 |
| `ending` | 冠軍、回顧清單 | 房主按再來一局 |

各階段的固定秒數（8 秒、6 秒）寫在 `config.js`。

### 5.2 遊戲推進

免費方案沒有伺服器端程式，所以遊戲推進由前端負責：

- 每個在線的裝置（玩家和大螢幕）每 500ms 檢查一次：目前階段的結束條件是否已滿足。
- 條件滿足時，對 `meta` 執行 transaction：只有 `phase` 和 `round` 還是自己看到的值時才寫入新階段。所以多台同時推進，也只會成功一次。
- 計票、淘汰都在 transaction 裡呼叫 `rules.js` 完成，結果寫進 `rounds/{n}/result`。
- 時間判斷一律用伺服器時間（本機時間 + `.info/serverTimeOffset`）。

### 5.3 身分與連線

- 使用 Firebase Anonymous Auth，`auth.uid` 就是玩家 ID。重新整理後身分不會變，會自動回到原本的房間和階段。
- 用 `onDisconnect` 維護 `players/{uid}/online`。
- **房主轉移**：房主離線超過 10 秒，就由在線玩家中最早加入的人接任房主。這個轉移也用 transaction 寫入。
- 斷線玩家的處理：
  - 拍照時間內回來，照常可以送出。
  - 時間到還沒回來，照超時規則出局。
  - 斷線的人不計入「所有人都投票了」的判斷。

### 5.4 資料結構

```
rooms/{roomCode}
  meta
    hostId: string
    phase: "lobby" | "capture" | "reveal" | "vote" | "revote" | "result" | "ending"
    round: number                      從 1 開始
    phaseEndsAt: number                伺服器時間戳（ms）
    settings: { captureSec, voteSec, customOnly }
    usedPromptIds: { [promptId]: true }
    createdAt: number
    updatedAt: number
  players/{uid}
    name: string                       1～8 字
    joinedAt: number
    online: boolean
    alive: boolean
    eliminatedRound: number | null
    eliminatedBy: "timeout" | "vote" | null
  screens/{uid}
    online: boolean
  customPrompts/{promptId}
    text: string                       1～20 字
    authorId: string
  rounds/{n}
    prompt: { id, text, authorId | null }
    photos/{uid}: string               base64 JPEG
    timeouts: { [uid]: true }
    candidates: { [uid]: true }
    votes/{voterUid}: targetUid
    revote: { candidates: { [uid]: true }, quota: number, preEliminated: [uid], votes: { [voterUid]: targetUid } }
                                       preEliminated：重投前就確定出局的人（3.6 quota = 2、第一名一人、第二名平手），
                                       result.eliminated 會包含他們
    result: { tally: { [uid]: number }, eliminated: [uid], reason: "vote" | "tie" | "noVotes" }
  ending
    winnerId: string
    worstPhotos: [{ round, uid }]
```

### 5.5 照片

- 用 `getUserMedia` 取得影像，再用 canvas 擷取。
- 裁成 3:4，長邊 800px，輸出 JPEG，品質 0.7，目標 150KB 以下。
- 壓縮後超過 300KB 就降低品質重新壓縮。
- 舊房間清理：建立新房間時，刪除 `updatedAt` 超過 24 小時的房間。

### 5.6 安全規則重點（`firebase/database.rules.json`）

- **登入**：所有讀寫都要先通過 Anonymous Auth。
- **`players/{uid}`**：只有本人可以寫。房主可以刪除（踢人）。
- **推進寫入的欄位**：遊戲推進由任何在線裝置執行（5.2），所以房間成員（玩家和大螢幕）都可以寫以下欄位，並驗證當下的 `meta.phase`：
  - `players/{uid}` 的 `alive`、`eliminatedRound`、`eliminatedBy`：只能在 `phase` 不是 `lobby` 時改（遊戲進行中，以及「再來一局」重設時）。
  - `rounds/{n}` 的 `prompt`、`timeouts`、`candidates`、`revote`（不含 `votes`）、`result`。
  - `ending`。
- **`photos/{uid}`**：
  - 只有本人可以寫，而且只能寫一次。
  - 只能在 `phase == "capture"` 且時間未到（含 2 秒緩衝）時寫入。
  - 字串長度不能超過 400000。
- **`votes/{voterUid}`**：
  - 只有本人可以寫。
  - 不能投自己，投的對象必須是候選人。
  - 只能在 `vote` 或 `revote` 階段寫入。
- **`meta`**：房間成員都可以寫，因為推進需要，但要驗證 `phase` 是合法值。
- **刪除房間**：只有 `updatedAt` 超過 24 小時的房間才能刪除。

### 5.7 外部資源

全部透過 CDN 載入，版本號寫在 `config.js`：

- Firebase JS SDK（modular 版本，從 gstatic 載入）
- QR code 產生器
- Google Fonts：Noto Sans TC

### 5.8 本機開發

- **啟動**：在專案根目錄執行 `python3 -m http.server 8000`，再打開 `http://localhost:8000`。
- **Firebase 模擬器**：連到 `localhost` 時，`config.js` 會自動改連模擬器，執行 `firebase emulators:start --only auth,database`。
- **相機**：瀏覽器只允許在 HTTPS 或 localhost 使用相機。要用手機測試，請部署到 GitHub Pages 的測試分支，或使用 HTTPS 通道。

## 6. 內容格式

### 6.1 內建題庫 `data/prompts.json`

```json
[
  { "id": "color-yellow", "text": "黃色的東西", "category": "color" }
]
```

- **`id`**：`分類-英文描述`，用 kebab-case，不能重複，新增之後不要改。
- **`text`**：繁體中文，20 字以內，以「的東西」或名詞結尾，必須是在一般室內能找到的物品。
- **`category`**：
  - `color`：顏色
  - `shape`：形狀
  - `texture`：材質觸感
  - `function`：用途
  - `abstract`：抽象感覺
  - `fun`：搞笑
- **題目風格**：
  - 要讓不同的人拍出不一樣的東西，避免只有一種答案的題目（例如「時鐘」）。
  - 要讓拍得好壞有差別，才有投票的笑點。

### 6.2 介面文字 `i18n/zh-TW.js`

```js
export default {
  home: {
    createRoom: "建立房間",
    joinRoom: "加入",
  },
  errors: {
    nameTaken: "這個暱稱有人用了，換一個吧",
  },
};
```

- key 用 `畫面.用途`，用 camelCase。
- 有變數的文字用 `{name}` 佔位，例如 `"出題者：{name}"`。
- 語氣：口語、輕鬆，像朋友在旁邊提醒。不用「請」，不用驚嘆號堆疊，錯誤訊息要說怎麼解決。
