# 測試清單

改完程式後，依照改動範圍跑對應的項目。回報時說明跑了哪幾節、哪些沒跑。

## 1. 自動測試：遊戲規則

執行 `node --test`，每次提交前都要全部通過。

| 檔案 | 測什麼 | 需要模擬器 |
|---|---|---|
| `tests/rules.test.js` | 遊戲規則（下表 R1～R19） | 不用 |
| `tests/engine.test.js` | 每一種階段轉換寫入的內容、房主轉移 | 不用 |
| `tests/database-rules.test.js` | 安全規則：用 REST 對模擬器實際寫入，確認該擋的有擋 | 要 |

改到 `firebase/database.rules.json` 時，先啟動模擬器再跑 `node --test`。模擬器沒開時 `database-rules.test.js` 會整組跳過，這時不能算有測到安全規則。跳過時輸出裡會有一行 `﹣ 安全規則 # 模擬器沒開`，總測試數也會少 30 項左右；最下面的 `ℹ skipped` 仍然是 0，不要看那一行判斷：

```
PATH="/opt/homebrew/opt/openjdk@21/bin:$PATH" firebase emulators:start --only auth,database
```

（Java 用 Homebrew 的 `openjdk@21`，沒有加進 shell 設定，所以在指令前面指定路徑。）

`tests/rules.test.js` 至少要涵蓋以下情境。改到 `rules.js` 時，要先確認這些情境都有對應的測試，再新增這次改動的情境。

| # | 情境 | 預期結果 |
|---|---|---|
| R1 | 5 名候選人，A 3 票、B 1 票、C 1 票 | A 出局 |
| R2 | 5 名候選人，A 2 票、B 2 票 | A、B 重投，淘汰 1 人 |
| R3 | 重投 A 2 票、B 2 票 | 沒人出局，原因 `tie` |
| R4 | 全部棄權 | 沒人出局，原因 `noVotes` |
| R5 | 7 名候選人，A 4 票、B 3 票 | A、B 出局 |
| R6 | 7 名候選人，只有 A 有得票 | 只有 A 出局 |
| R7 | 7 名候選人，A 3 票、B 3 票 | A、B 出局，不用重投 |
| R8 | 7 名候選人，A 2 票、B 2 票、C 2 票 | A、B、C 重投，淘汰 2 人 |
| R9 | 7 名候選人，A 4 票、B 2 票、C 2 票 | A 出局，B、C 重投，淘汰 1 人 |
| R10 | 重投要淘汰 2 人，結果 A 3 票、B 1 票、C 1 票 | A 出局，其餘不淘汰 |
| R11 | 4 名存活，2 人超時 | 2 人出局（`timeout`），剩 2 名候選人，`quota = 1` |
| R12 | 3 名存活，全部超時 | 本輪作廢，沒人出局 |
| R13 | 3 名存活，2 人超時 | 剩下的 1 人獲勝 |
| R14 | 8 名存活，2 人超時 | 剩 6 名候選人，`quota = 1` |
| R15 | 投給自己、投給非候選人 | 該票無效，不計入 |
| R16 | 只用自訂題目開啟，自訂題目 2 題、已用 1 題 | 抽到剩下那題 |
| R17 | 只用自訂題目開啟，自訂題目用完 | 改從內建題庫抽，不重複，並標示要顯示提示 |
| R18 | 只用自訂題目關閉 | 自訂和內建混在一起抽，不顯示提示 |
| R19 | 所有題目都用過 | 清空已用紀錄，重新開放全部題目 |

## 2. 本機多人測試

準備：

1. 執行 `firebase emulators:start --only auth,database`。
2. 執行 `python3 -m http.server 8000`。
3. 用不同的瀏覽器設定檔或無痕視窗開 3～4 個分頁，每個分頁是一位玩家。同一個瀏覽器的一般分頁會共用登入身分，不能拿來模擬多人。
4. 可以在 Chrome DevTools 的 Sensors 或用假影像（`--use-fake-device-for-media-stream`）模擬相機。

### 2.1 開房與等待室

- [ ] 建立房間，拿到 4 位數房號
- [ ] 其他分頁用房號加入，名單即時更新
- [ ] 重複的暱稱會被擋下
- [ ] 第 13 人加入時顯示「房間已滿」
- [ ] 每人最多出 3 題，第 4 題會被擋下
- [ ] 一般玩家看不到別人的題目，房主看得到，也可以刪
- [ ] 房主改設定，其他人畫面同步
- [ ] 房主踢人，被踢的人回到首頁並看到提示
- [ ] 2 人時按開始會出現提示，不會開始
- [ ] 等待室按重新整理，直接回到等待室，不會回到首頁
- [ ] 打開別人分享的 `?room=房號` 連結，房號已填好，畫面只有暱稱和加入；按「改加入別的房間」回到一般首頁
- [ ] 3 人時按開始，所有人的畫面離開等待室
- [ ] 斷線的玩家在名單上變灰，回來後恢復

### 2.2 一輪完整流程

- [ ] 所有分頁的倒數一致（差距 1 秒以內）
- [ ] 拍照後可以重拍，按送出後不能再改
- [ ] 所有人送出後提前進入揭曉
- [ ] 揭曉照片牆顯示所有照片和名字
- [ ] 投票時自己的照片不能點，可以改票
- [ ] 結果正確顯示票數和出局者
- [ ] 出局玩家下一輪看到觀眾畫面，仍然可以投票
- [ ] 第一輪按「打開相機」後，第二輪起不用再按，直接是取景畫面
- [ ] 出局後頂部顯示「你已出局，繼續投票吧」，相機指示燈熄滅
- [ ] 揭曉的照片逐張翻開，點照片放大；投票時點放大鏡才放大，點照片是投票
- [ ] 倒數剩 10 秒變紅並跳動；結果畫面出局者卡片晃動後變灰

### 2.3 規則情境（手動）

- [ ] 有人不送出：時間到直接出局，揭曉時列在超時名單
- [ ] 製造第一名平手：進入重投，只顯示平手的人
- [ ] 重投再平手：顯示「這輪沒人出局」並進下一輪
- [ ] 全部不投票：顯示「這輪沒人出局」
- [ ] 剩 2 人的決賽：觀眾的票決定結果
- [ ] 剩 1 人：進入結束畫面，顯示冠軍
- [ ] 超時後只剩 1 人：先進揭曉，沒拍到的人顯示叉叉，標題「只剩 xx，冠軍出爐！」，5 秒後進結束畫面
- [ ] 有人超時但還剩 2 人以上：揭曉時超時的人顯示叉叉，接著照常投票

### 2.4 斷線與房主轉移

- [ ] 拍照中重新整理：回到拍照畫面，倒數正確，可以送出
- [ ] 投票中重新整理：回到投票畫面，已投的票保留
- [ ] 關掉房主分頁：10 秒後由最早加入的在線玩家接任房主
- [ ] 關掉房主分頁後，遊戲仍會照時間推進
- [ ] 斷網再連回：頂部顯示斷線提示，恢復後消失

### 2.5 結束與再來一局

- [ ] 結束畫面先顯示冠軍頁，不會自動跳頁；按「看最爛照片回顧 →」才到回顧頁，按「← 冠軍」可以回去
- [ ] 回顧照片可以左右滑，也會每 4 秒自動切換
- [ ] 整局沒人因投票出局：回顧頁顯示「這局沒有人被投票淘汰」，仍然有再來一局按鈕

- [ ] 回顧依輪次順序顯示每輪因投票出局者的照片
- [ ] 沒人因投票出局的輪次被跳過
- [ ] 再來一局：所有人回到等待室，暱稱和設定保留，自訂題目清空

### 2.6 大螢幕模式（v2）

準備：大螢幕開在無痕視窗（和玩家分頁不同身分），視窗放到最大。

- [ ] `?mode=screen&room=xxxx` 開啟，不出現在玩家名單、不算人數
- [ ] 首頁「大螢幕模式（投影用）」輸入房號也能連上；房號不存在時顯示提示
- [ ] 各階段顯示內容符合 SPEC 4.9
- [ ] 投票階段不顯示即時票數
- [ ] 10 人以上時：等待室名單、拍照的名字卡、兩排照片牆、結果的票數長條都放得下
- [ ] 結束畫面不會自動換頁，點按鈕才換
- [ ] 只開大螢幕、所有玩家暫時斷線時，大螢幕仍會推進遊戲（全部沒交 → 每 32 秒作廢換題）

## 3. 實機測試

部署到 GitHub Pages 後，用實體手機測試：

- [ ] iPhone Safari：相機可以開，前後鏡頭可以切換
- [ ] Android Chrome：同上
- [ ] 從 LINE 打開連結：顯示「請用 Safari 或 Chrome 開啟」的提示
- [ ] 拒絕相機權限：顯示開啟權限的說明
- [ ] 照片字串長度在 400000 以下（在 Firebase 資料畫面確認），大螢幕看得到照片
- [ ] 使用行動網路的手機和使用 WiFi 的手機同房遊玩正常
